# Changelog

## 2026-08-12

### Added

- **Quiver's warehouse is now verified as a usable input, and its bad data is flagged rather than trusted.** Checked the corpus mapping against the live Redshift warehouse: 247 merchants and 21.6M orders reaching back to 2021 and current to yesterday, with the column contract matching exactly and a real order mapped end-to-end. Two findings changed the design — orders arrive in six currencies (an order can be entirely non-GBP, so nothing may assume sterling), and 43,873 orders in the last year carry a discount larger than their own subtotal, three of them over £100,000. Jefe now flags implausible order money instead of quietly averaging it into a belief, and records what it flagged so a reviewer can see what was set aside rather than the data looking cleaner than it is. `tools/quiver-corpus/src/{map,quiver-schema}.mjs`.
- **Real merchants can now be replayed through Jefe as simulated stores.** Added `tools/quiver-corpus`, which maps orders from Quiver's Redshift warehouse into Jefe's canonical commerce records so the existing pipeline — deterministic beliefs, evidence, insights, goals, plan and action chat — can be run against real businesses and inspected in Ops, without a parallel pipeline or a bespoke parser. Corpus stores are structurally isolated from real tenants: they use a `quiver_sim` platform and an unresolvable `*.corpus.invalid` domain, so they carry no Shopify session or token and the action layer cannot write to any store from one. Customer emails are pseudonymised with a required salt, personal columns are off unless explicitly enabled, and Quiver's full stringified platform payload is never carried. The mapping layer and its write guards are built and covered by 18 tests; the data pull itself is still waiting on Metabase access, and the gaps in what Quiver can tell us — no stock, no cost, no per-line prices — are stamped onto every corpus store so a belief is never built on absence. `tools/quiver-corpus/`, `MANIFEST.json`, `.worktreeinclude`.

### Changed

- **The settings surface mounts its first real panel — Autonomy.** `/app/settings` (the new left-nav settings area) now renders the per-action autonomy roster — recommend / approve / autonomous dials, with live-vs-"Soon" driven by engine truth (`getLiveActionModes`) rather than hardcoded — from the roster session's `AutonomyPanel`, fed by the settings loader. The surface stays **unlinked** (no merchant reaches it yet) pending the founder's call on the home entry point; Channels, Integrations and the email-preferences panel mount into the same slot pattern as their lanes land. `app/routes/app.settings.tsx`.
- **Merchants can open Jefe in a full browser tab from inside Shopify.** `app.mynamejefe.com` is the standalone web app; the embedded Shopify shell now shows an "Open the app ↗" button (top-right) that signs the merchant into the same store on the web via `/standalone/auth` (which verifies the active install and mints a standalone session). Shown only once onboarding is complete, and never on the standalone surface itself. Host comes from config (`STANDALONE_APP_HOST`), not a hardcoded literal. `app/routes/app.tsx`.
- **The home no longer throws away its server render over a date mismatch.** `formatToday()`/`formatShortDate()` formatted dates with no pinned timezone, so the server (Railway, UTC) and the merchant's browser produced different calendar dates for the 00:00–01:00 London window every day — React saw a hydration mismatch (#418/#425), discarded the whole server-rendered home and re-rendered on the client (the wrong "Tuesday 11 August" header shown on the 12th). Both date helpers now pin one named `VIEWER_TIME_ZONE`, so SSR and client render identical text. Per-merchant timezone (the shop `ianaTimezone` the loader already fetches) is tracked as a follow-up so a non-UK store reads its own date. `app/components/daily-home.tsx`.
- **Memory correction works again after the home redesign — through the free-text composer.** The action-chat home redesign (PRs #65–79) orphaned the 13a Memory correction controls: the `memory.*` handlers + `beliefConfirmPriority`/authorship/`confirmState`/`sourceLine`/`statement` all still compute server-side, but nothing rendered them, so merchants could no longer confirm/correct/answer — only a bare free-text box. Per the founder's call — make it work *within the free-text composer*, not with per-belief buttons — the reachable Merchant Memory view (`?view=memory`) is now conversational: it renders Jefe's beliefs in **plain English with provenance** (the `statement`/`sourceLine` the loader already computed and this view ignored), **orders them by `confirmPriority`** (most worth confirming first), and **surfaces the open questions** only the merchant can answer. So a merchant confirms ("that's right"), corrects ("most of my sales are wholesale") or answers a question just by typing, and `memory.message` → `sendConversationMessage` interprets and commits it. No new buttons — the composer stays the single input. **Forget-by-typing is the one remaining gap:** it needs an `obsolete_belief` operation in the interpreter (chat 9's lane, coordinated) since the conversational path has no obsolete op today. **Also fixed the door:** the "See everything Jefe knows →" entry link lived inside the "What I'm watching" section, which returns null when there's nothing to watch — so on a quiet / all-clear home the memory surface was unreachable (found in live testing). The link now sits at the home level, always rendered; the reachability test was tightened to assert it's in the always-rendered composition, not just present somewhere in source. `app/components/merchant-memory-view.tsx`, `app/components/daily-home.tsx`.
### Fixed

- **Merchant Memory answers now stay inside the shop the merchant is asking about.** When a merchant runs more than one shop under the same account, the context Jefe assembles to answer a question inside a move could quietly include the other shop's beliefs, goals, insights, plan recommendations and action history — Jefe would have answered about the wrong shop with no sign anything was wrong. Every read is now scoped to one shop, and a request that arrives without a shop now reads nothing and records why, instead of reading everything. Shop-specific and account-wide beliefs are both still included, so nothing a merchant told Jefe about their business as a whole is lost. `app/lib/merchant-memory/context-retriever.server.js`, `tests/merchant-context-retriever.test.mjs`.
