## Operating model — draft → approve → post (not autonomous)

The agent **drafts**; Matt **approves**; then it posts. Never autonomous posting or replying. Why, deliberately:
- **Brand risk** — an AI posting/replying unsupervised can misfire in public, permanently.
- **Platform ToS** — LinkedIn and X actively throttle/ban automated engagement.
- **Same rule as the product** — nothing real goes out without Matt's OK.

It **earns** more automation as it proves itself (bulk-approve → scheduling → a suggested-reply feed) — the same *advisory → earns autonomy* model as Jefe itself. Fed by the [case studies](case-study-template.md), the build, and the thesis.

## Content pillars (rotate)

1. **Build-in-public** — what we shipped/learned this week; a founder building an AI eCommerce manager in the open.
2. **The thesis** — Merchant Memory: why "an AI that actually understands your store" beats another dashboard or chatbot; the advisory→autonomy ramp.
3. **Design-partner journey** — the *aha* moments and wins (consented only), the "first e-commerce managers" story.
4. **Operator value** — a concrete weekly decision a Shopify operator makes, and how Jefe handles it (reorder, budget shift, price match, returns — the site's own examples).
5. **Engagement** — reply to DTC founders/operators talking about the exact pains Jefe solves (drafted replies, Matt approves).

**Cadence (sustainable, ramp up):** LinkedIn 2–3×/week (Matt's founder voice), X 3–5×/week + a daily engagement window. Start lighter.

**Voice:** warm, personified ("my name is Jefe"), specific, confident-not-hypey, receipts-driven. Never overclaim autonomy — present tense is advisory; actioning is what Jefe *earns*.
